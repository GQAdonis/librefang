# Design

The production binary is `bossfang` (Windows: `bossfang.exe`). The Boss starts it with `--config <private absolute path> start --foreground --bind 127.0.0.1:<resolved port>`, supplies `BOSSFANG_HOME` for its isolated state, waits for `/api/health`, and embeds `/dashboard/`. The explicit config file must exist before launch; an empty TOML file uses compiled defaults but its `home_dir` should be set to the Boss-owned state directory. The Boss must provision dashboard credentials before launch. Its existing authentication accepts `dashboard_user` in private config together with `LIBREFANG_DASHBOARD_PASS` in the child environment, or a `dashboard_pass_hash` Argon2id verifier in config. Native login issues a dashboard-scoped HttpOnly cookie and an API bearer token to BossFang's own SPA. Without a configured dashboard username and password/hash, local loopback is trusted as Owner and the native dashboard does not prompt for login; The Boss must reject that managed startup posture.

BossFang already serves the Vite SPA from compile-time `static/react` through `include_dir!` and defaults to embedded-only mode. No dashboard UI is copied into The Boss and no runtime asset download is needed. The release build sets `BOSSFANG_REQUIRE_EMBEDDED_DASHBOARD=1`. The build script runs the existing frozen pnpm install and Vite build, then requires `static/react/index.html` with `/dashboard/` base and nonempty JavaScript and CSS assets. `SKIP_DASHBOARD_BUILD=1` is invalid for a clean release build unless these assets were built explicitly beforehand.

Apple Silicon and Windows x64 binaries are built on their native runners from one pinned source revision. The Boss installer carries each executable in `resources/binaries/<platform>/`; its packaging gate checks the binary, checksum, and actual `/dashboard/` response. A successful Rust compile alone does not satisfy the C14.3 integration gate.

The dedicated `bossfang-sidecar-payload` workflow takes an exact 40-character source commit and builds only these two native payloads. It prebuilds the dashboard, then runs Cargo with `SKIP_DASHBOARD_BUILD=1` and the strict embedded-dashboard guard. `scripts/package-bossfang-sidecar.mjs` writes a binary checksum and manifest containing the exact source commit and dashboard asset digest. Workflow artifacts are staging payloads for The Boss; this workflow does not publish or overwrite a BossFang GitHub Release.
