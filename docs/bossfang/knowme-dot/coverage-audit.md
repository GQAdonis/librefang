# KnowMe dot capability audit (2026-10-16)

This is an independently designed, observable capability target for the private KnowMe dot. It does not describe or reproduce OpenAI internals. **Documented** means a requirement or issue exists; **implemented substrate** means source contains a relevant primitive; **tested** is reserved for evidence from the exact final integration build. No end-to-end dot or meeting mode was tested in this audit. An issue is never implementation evidence.

## Finite release sequence

1. **M0 definition and authority:** pin versioned agent profiles, owner conversation binding, closed dispatch inventory, exact approval/receipt contract, and synthetic two-owner adversarial fixtures. Existing #156 and UAR dependencies govern this milestone.
2. **M1 owner call:** one authenticated owner calls their dot in one chat. Pass VC01–VC17 and the eight proposed voice gates on a declared platform, route, hardware and language matrix. Media worker has no independent effect authority. No PSTN or third-party dialing.
3. **M2 online meeting participant:** qualify one explicitly named meeting platform or owner-controlled room after invitation/host approval, participant disclosure and consent. Verify join/leave receipts, floor-taking, privacy, group-answer controls and recovery. A generic WebRTC proof is insufficient for Teams/Zoom/Meet compatibility.
4. **M3 in-person mobile companion:** qualify foreground capture and explicit consent on one physical mobile matrix. Background/lockscreen is a separate platform gate. Run the fictional report scenario in [meeting-modes.md](meeting-modes.md).
5. **M4 optional rich media:** qualify self-hosted/hosted LiveKit-style adapters, authorized interactive avatar and audio/video interpretation independently. Model name, license, region and vendor claims need verification.
6. **M5 outbound human calls:** separate carrier and takeover qualification with exact owner approval; no real calls in this audit.
7. **Stop:** each milestone ends when its frozen required predicates pass on exact revisions, or records a named blocker and owner decision. Optional capabilities become new proposals; do not silently expand the phase.
