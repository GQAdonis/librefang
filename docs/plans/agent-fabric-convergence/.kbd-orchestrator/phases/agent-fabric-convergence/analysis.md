# Analysis: agent-fabric-convergence

This stage reuses the five completed research packages and proposed standard, then reconciles their design choices with the fetched source evidence. No new framework or dependency is selected from memory. External library versions and mutable protocol documentation must be refreshed through Context7/primary sources when a concrete implementation adopts them. This is reuse analysis, not a repeat landscape survey or a claim of fresh upstream validation.

## Decisions

1. **Use the existing UAR host.** Extend its thread, actor, compiler and policy boundaries for teams. A second token/tool loop would conflict with existing attenuation and mobile embedding. A team coordinator schedules distinct bounded runs; BossFang may own a larger application workflow containing those runs.
2. **Adopt the current P1 integration as a dependency.** The new UAR driver and BossFang HTTP provider bridge supersede earlier missing-foundation findings. Agree checkpoint, history vocabulary and file ownership before changing their shared interfaces. The initiative must not absorb or delay the other task's current delivery.
3. **Separate logical identities.** Definitions, installations, activations, threads/runs, team/workflow instances, service instances, provider endpoints, human subjects and office assignments have different lifetimes. A private port and a role title are not authority. Preserve native IDs under explicit namespaced mappings.
4. **Use explicit deployment profiles.** Preserve independent UAR/BossFang/Forge operation, optional Gate/Fabric, local embedded KnowMe and remote/home configurations. A required unsupported capability blocks placement; optional degradation is visible and never expands authority.
5. **Close real action boundaries before expanding authority.** Build on Cedar and host approval/budget machinery. Revalidate the direct, managed, embedded, queued and remote paths; authenticate instance/subject, bind the exact target and payload, compose independent boundaries restrictively, and recheck before effect. Cedar does not implement quota transactions, revocation distribution or external-effect atomicity.
6. **Extend UAR-AGENT-MD.** Preserve section-based legacy authoring and typed IR. Define five versioned document kinds with loss diagnostics and required-field rejection. Portable documents request capabilities; installed principals and representation grants stay in a private authority plane.
7. **Default to request execution or on-demand actors.** Durable state and mailbox identity are separate from residency. Measure residency and cross-host takeover needs before enabling pinned processes or transparent failover. One logical mutating turn at a time initially; cancellation/admin control stays out of that queue.
8. **Make observation a governed delivery path.** Use stable occurrence identity, per-observer inbox/cursor, an outbox at the source commit boundary and independent source/recipient checks. BossFang channel handling and observer copies have distinct routing and response rights. In-memory SSE is not a durable subscription.
9. **Preserve three data paths.** Personal authorized CRDT documents, server-authoritative business read projections, and durable offline business commands have separate stores/versions/acknowledgements. Runtime ownership, grants, budgets and external effects do not become arbitrary multi-writer CRDT objects.
10. **Start business effects with feedback intake.** Observe → classify → draft → scoped standing-policy issue creation → product/design review. Keep customer communication, roadmap promises, publication and financial actions separately authorized. Expand to marketing, design and executive support only after the governing boundaries work.
11. **Reuse the merged skill family and adapters.** Add guided role selection, reviewed skill locks and business presets through the existing creator/models/manage/handoff contracts. Keep all eight requested harnesses, including MiniMax's own CLI and DeepSeek Harness. Preserve native options with explicit passthrough/validation or unsupported diagnostics; never claim all harnesses have identical teams/plugins/marketplaces.
12. **Prefer an isolated service-console view for BossFang.** The Boss controls common connections, instances, approvals, runs, budgets and subscriptions. BossFang retains channel-specific administration. KnowMe retains personal UX and consent. Do not broaden every packaged mini-app's privileges to embed one console.

## Decision gates retained in scope

The plan resolves sequence and ownership now. Implementation must resolve: exact governed mobile profiles; in-process storage compatibility; current P1 history and approval contracts; peer recovery and offline grant validity; connector idempotency; workflow-engine need; permitted organizational grant issuers; external-runtime trust evidence; automatic failover prerequisites. Each gate is assigned to a delivery slice. None may be silently replaced with a favorable assumption.

The existing report scores are not baseline performance measurements. C18 defines comparison against single-agent and relevant harness baselines with the same model/tool/budget conditions where feasible. A quality or security result on one task family cannot certify a different family.

## Independent review disposition

C10 must first produce workflow requirements before choosing an engine: recovery model, embedding/mobile/offline constraints, effect idempotency, scheduler ownership, throughput and operational cost. No external engine is selected.
