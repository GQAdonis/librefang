# Proposal
## Why
The current combined delivery is stuck at failed feature operation despite repeated successful builds. Two localized approval/observation contract defects are identified; the parent needs an executable recovery order and the operator's full/local/full two-hour cadence.

## What Changes
- Install the reviewed R1–R3 repair handoffs in existing parent plans and product changes, preserving requirements and task identities.
- Configure the existing cadence for 120-minute usable increments, local Mac ARM64 build/operation each, and four-platform GitHub/website publication on recovery deliveries 1, 3, 5.
- Preserve failure history, legacy publication obligations, scoped ownership and model routing.
- Reflect and restore the parent before parent ready/success. Product implementation, builds and publication run there, not as a competing child scheduler.

## Capabilities
### New Capabilities
None. This change installs planning and execution configuration; it does not introduce a runtime capability.
### Modified Capabilities
None. Existing product requirements remain authoritative. Specs are deliberately skipped for this tooling/documentation change; no synthetic runtime requirement is added.

## Impact
Initiative authored planning/dispatch documents and supported Cadence configuration. No runtime API, dependency, product code, application build or service change in this recovery change. Parent product repair boundaries are in the child's plan.md. Completed recovery tasks do not increase the parent product completion counter.
