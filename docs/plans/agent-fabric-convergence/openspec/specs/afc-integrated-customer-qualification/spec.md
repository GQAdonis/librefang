## Requirements

### Requirement: Candidate-specific customer qualification
Customer qualification SHALL name exact source, binary and operational evidence, separate code completion from qualification, publish Mac ARM64 and Windows x64 installers and retain missing installed acceptance.

#### Scenario: Completed delivery boundary
Given an integrated candidate, when customer closeout is recorded, then actual packaged operation and live website receipts identify it; previous candidate acceptance and unavailable native operation cannot be relabeled as passing.

### Requirement: Accepted core scope and preserved unresolved qualification
Core customer closeout SHALL retain exact Mac ARM64 and Windows x64 acceptance and applicable release evidence. Representation qualification SHALL remain separately unresolved, without changing historical implementation or portfolio counters.

#### Scenario: Operator excludes representation from core milestone
Given explicit operator scope approval and both exact 2.2.32 installer acceptances, when the core milestone closes, then representation evidence remains preserved and its follow-up remains open; no new read, approval cycle, delivery count or representation pass is created.
